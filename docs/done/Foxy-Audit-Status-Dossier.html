00 · The no-fakes audit — read this first

What's genuinely live vs. still stubbed

Four independent source audits + a live check against the production instance. The core spine is real and running. Four things are not what a casual reading of the old dossier implied — they're listed here plainly, with severity, before any of the good news.

Claim / surface Reality The honest detail
"Anchoring live on Sepolia"
the headline trust USP
 Stubbed in prod The AnchorRegistry contract is deployed on Sepolia (0x4D4F…) and the evm provider is real web3 code, exercised in dev. But production defaults to ANCHOR_PROVIDER=stub (a simulated tx) and a live check of the prod org returned /v1/anchors = [], /v1/verify → count 0, last_anchor null — prod has anchored nothing. To make it true: set ANCHOR_ENABLED=true + the EVM vars on the VM and restart the worker.
Desktop "Auditor Console" tiles
block height · chain root · score
 Synthesized The desktop app's KPI tiles are still computed locally (sha256 of local state; the score self-heals +0.1/sec) — not fetched from the backend. The web dashboard's numbers are real; only the secondary desktop console fakes them. Fix: point those tiles at /v1/stats + /v1/verify, or drop them.
Sales page — small print
contact form + a few links
 Placeholders The contact form silently drops the message (sends only name+email). The "Download" button + footer/support links still point at bare github.com, and the install snippet says …/yourusername/…. (The fake Stripe checkout and the wrong foxychat.ai domain are already gone.)
Web dashboard — stray labels
cosmetic, static-in-HTML
 Stale copy A hardcoded "Yo Fatima" greeting, a "42ms judge latency" stat, and a "Gemini 1.5 Pro" label (the backend actually runs gemini-2.5-flash). The big event counters are overwritten with real API data on load; these three are not.
Bottom line, stated plainly
The backend platform is real and production-live — chain, verification, durable ingest, enforced RLS, the AI judge, auth, billing, and every Phase-5/6 feature run for real on foxyaudit.tech. The four items above are the honest exceptions: one config flip (prod anchoring), one secondary-surface rework (desktop tiles), and cosmetic web cleanup. None of them touch the cryptographic core.

02 · What shipped since this dossier's last cut

Phase 5 & 6 — from pilot-ready to production

The previous dossier reflected Phase 4. Two full phases have landed since, all TDD'd (red→green), and pushed to main (3485f34) with a green CD run that deployed to the VM.

Phase 5 · production hardening (5A–5L)

Correctness fixes (breach-reaction poller, Stripe provisioning, analytics); security (email-OTP MFA via Brevo, RLS actually enforced via a confined role, login rate-limit + rotation, security headers, request-size cap); missing SaaS features (password reset, invites, workspace soft-delete, data export, retention); reliability (dead-letter alerts, worker circuit-breaker + graceful drain, correlation IDs + structured logs, deploy smoke-test + rollback, backups); dependency pinning; theme trim (14→1); AI/PII depth (temporal judge + Presidio); per-org dashboard IP allow-list, noindex, and login history; plus desktop tray popup, sound cue, and weekly summary.

Phase 6 · differentiators (6A–6E)

Self-serve onboarding (free signup + paid Stripe Checkout + real credential delivery); agent-level attribution folded into the tamper-evident chain; an embeddable public trust badge; a standalone open-source verifier (re-verify without trusting Foxy); and a per-tier anchor-frequency SLA. Migrations advanced to a single head 0027. (ZKP work remains explicitly out of scope by team decision.)

05 · The honest road ahead

What's genuinely left

Phases 1–6 are shipped to main and deployed. What remains splits into: the four audit gaps (§00), a couple of ops flips, and the enterprise/legal tier that's always separate from code.

Close the audit gaps

  • Flip prod anchoring on — set ANCHOR_ENABLED=true+evm+contract/RPC/funded-key on the VM, restart the worker, confirm a real chain=sepolia anchor. Then the headline claim is true.
  • Real desktop console tiles — point block-height/root/score at /v1/stats+/v1/verify, or remove them.
  • Web cleanup — send the contact-form message; fix the github.com/yourusername links; drop the "Yo Fatima"/"42ms"/"Gemini 1.5 Pro" static copy.

Ops flips (config, not code)

  • Arm paid checkout — paste Stripe price_… IDs into the VM deploy/.env.
  • Rotate exposed secrets — the chat-exposed Brevo key, Stripe test keys, session secrets, and the funded Sepolia key in backend/.env (gitignored, but real). Deferred by team decision to now-ish.
  • Desktop #2 + #6 — add an "Open web dashboard" tray link; repro + fix the sprite translucency on affected devices.

Product depth — Phase 7

  • Anchor monitoring — alert on failed/stale anchors + a wallet-balance check once evm is on.
  • Mainnet / L2 instead of Sepolia, with funded operational key management.
  • Per-tenant dashboard branding + mobile polish.

Enterprise gates (business, not code)

  • SSO / SAML / MFA-for-enterprise, SCIM.
  • SOC 2, data residency, uptime SLAs, BAA — months + money, independent of code quality.
  • Contractual notarization of the passport if buyers ask.
Bottom line
The product does the thing on its headline promise — a real web dashboard, durable ingest, enforced tenant isolation, an AI judge that reasons over time, a tamper-evident chain, and self-serve onboarding — all deployed and green. The remaining work is one anchoring flip, one secondary-surface rework, cosmetic cleanup, and the enterprise tier. This dossier names every gap rather than rounding them up.
