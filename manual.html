One thing trips up almost every judge, so we're putting it on page one: WhatsPlan is a website with a small Chrome extension attached to it — not the other way around. The extension is a popup that shows your planner; it doesn't contain the app.

The website
The real product. Connect WhatsApp, watch the AI sort live messages, try the six board types, switch between the eight themes, meet the pixel cat. Nothing to install.

  • Where AI reading gets turned on per chat

A lightweight companion popup — meetings, tasks, and announcements, one click away from the toolbar. It only shows data once the website has already sorted something.

Section 01

See the product — no install needed

This is the fastest path to judging WhatsPlan. Open the site, connect a WhatsApp account, and watch a real group chat turn into a planner.

1Open the site

Visit the live deployment in your browser. It's already running — there's nothing to clone, build, or configure.

# live deployment https://whatsplan.social

2Link a WhatsApp account

a
Click Connect
A QR code appears. This uses the official WhatsApp Web bridge — the same mechanism WhatsApp itself uses for linked devices.
b
Scan it from your phone
On the phone with the WhatsApp account you want to demo: WhatsApp → Settings → Linked devices → Link a device, then scan.
c
Wait for the green dot
The status indicator moves from connecting (yellow) to ready (green) once the session is live. No password is ever requested — your WhatsApp account is the identity.

3Turn AI reading on for one chat

By design, WhatsPlan reads nothing until you opt a specific chat in. This is the one extra step most demos forget, and it's the reason an empty planner doesn't mean something's broken.

a
Pick a chat, flip its AI toggle
Each chat in the list has its own switch. Flipping it on is the opt-in.
b
Verify your email — one time
A 6-digit code is sent to confirm it's really you before any reading starts. Enter it in the dialog that appears.
c
Send a test message
From the linked phone (or have someone else in the chat send one), try something like "standup tomorrow 9am, zoom.us/j/123". Watch it land in the Planner within a couple of seconds.
Note for judges Verification stays valid for a short window, then WhatsPlan asks you to re-verify before reading any new chat. That's intentional — it's a safety gate, not a bug, and it's documented behavior, not a glitch you've hit.

4Explore the rest

AreaWhat to try
PlannerMeetings, Tasks, and Announcements groups fill up live. Tick a task to complete it, pin an announcement, click into a meeting to confirm the extracted time and link.
BoardsSix board types — Kanban, Table, Roadmap, Calendar, Checklist, Notes. Drag a card between Kanban columns; everything persists to the backend.
ThemesEight full themes (Classic, Dark, Neo-Brutalist, Claymorphism, Glassmorphism, Neon, Skeuomorphic, Paper & Ink), all built on WhatsApp's own green.
Pixel catAn animated sprite companion roams the screen, reacts to typing and scrolling, and nudges you about open tasks.
Section 02

Install the companion extension

Optional, and best tried after Section 01 — the popup has nothing to show until the website has linked WhatsApp and classified at least one message.

What this extension actually is A small Manifest V3 popup. No build step, no bundler — Chrome loads the folder's files directly. It polls the live WhatsPlan backend every five seconds and mirrors the Meetings / Tasks / Announcements you'd see on the website, in a toolbar-sized window. By default it points at the live deployment, so it works the moment it's loaded.

1Locate the extension folder

Inside the submission, find the folder named extension. Open it and confirm you can see manifest.json directly inside — that's the folder Chrome needs.

extension/ ├── manifest.json ← this file must be directly inside the selected folder ├── popup.html ├── popup.css ├── popup.js ├── content.js └── icons/

2Turn on Developer mode

a
Open Chrome
Type chrome://extensions into the address bar and press Enter.
b
Flip the toggle
Top-right corner — switch Developer mode ON. Three new buttons appear at the top-left.

3Load the folder

a
Click "Load unpacked"
A file browser opens.
b
Select the extension folder itself
Click once to highlight the folder that holds manifest.json — don't open it and select individual files.
c
Confirm
"Select Folder" on Windows, "Select" on Mac. WhatsPlan now appears in your extensions list.

4Pin and open it

a
Click the puzzle-piece icon
Top-right of Chrome's toolbar.
b
Find WhatsPlan, click the pin
This pins the icon to the toolbar for one-click access.
c
Click the icon to open the popup
It connects to whatsplan.social automatically — no setup needed if you're judging the live deployment.

One extra step the popup needs

The popup authenticates using a session id it reads from an open WhatsPlan tab. Keep a whatsplan.social tab open (signed in) at the same time you use the extension — that's how it knows it's you.

Section 03

What you should see, and when

A quick reference so an empty screen never gets mistaken for a broken one.

The popup's three states

Red dot — backend unreachable. Check your internet connection, or that the live site loads in a tab.
Yellow dot — backend is up, WhatsApp session is still connecting (booting, awaiting QR scan, or just authenticated).
Green dot — fully connected. If lists are still empty here, it's because nothing's been classified yet — see below.

What a populated planner looks like

This is the same view on the website and in the extension popup — three groups, live counts, plain-language cards.

Meetings 1
Standup9:00 AM · zoom.us/j/928… · Team Alpha
Tasks 1
Finish API docs@sara · due EOD · Team Alpha
Announcements 1
Office closed Friday (pinned)Team Alpha

Why a list might stay empty

SymptomReason
Green dot, all lists emptyNo chat has AI reading turned on yet, or no new message has arrived since it was enabled.
One group empty, others fineWorking as intended — that chat simply hasn't produced that type of item. Send a message that matches it (e.g. "@name finish X by Friday" for a task).
A meeting shows "needs a time"The AI extracted a meeting but couldn't pin down a time from the message — open it on the website to fill it in.
Section 04

Troubleshooting for judges

IssueFix
"Manifest file is missing or unreadable" when loading the extension You selected the outer submission folder, not the inner one. Go back into it and select the specific subfolder that has manifest.json directly inside it — usually named extension.
Popup says "Open whatsplan.social in a tab… then hit refresh" Open the live site in another tab while signed in, then click the ⟳ refresh button in the popup.
Popup shows a settings panel instead of the planner First run only. The default backend URL is pre-filled — just click Save, no typing required, unless you're pointing it at a local dev server instead.
QR code on the website expires before you scan it Refresh the connect screen for a new code — these are short-lived for security, same as WhatsApp's own linked-devices flow.
Verification code email never arrives Check spam first. If testing against a local/dev deployment rather than the live site, the code may be printed to the server console instead of emailed (see Section 06).
Chrome blocks the extension after loading Make sure Developer mode is still ON — Chrome occasionally re-disables unpacked extensions after a relaunch. Re-toggle it and the extension reactivates without reloading the folder.

Judging checklist

  • Opened whatsplan.social directly — no install required for this part
  • Scanned the QR and saw the status dot turn green
  • Verified email and flipped AI reading on for one chat
  • Sent a test message and watched it land in the Planner within seconds
  • Tried at least one Board type and one theme switch
  • (Optional) Loaded the extension folder and pinned the popup
Section 05 — Optional, for technical review

Running it locally instead

Not required for judging — the live deployment already covers everything. Use this only if you want to inspect the code running end-to-end on your own machine.

Docker (recommended)

git clone <this-repo-url> && cd WhatsPlan cp server/.env.example server/.env # optional — works without keys docker compose up --build

App → http://localhost:8080  ·  API → http://localhost:4000

Without Docker (Node 20+)

# terminal 1 — backend cd server && npm install && npm run dev # :4000 # terminal 2 — frontend npm install && npm run dev # :8080
Zero API keys required Without a Groq key, message sorting falls back to a keyword-based heuristic classifier. Without a Brevo key, the verification code prints to the server console instead of emailing. Both work out of the box — keys just upgrade accuracy and delivery.

Pointing the extension at a local server

Open the popup → settings (gear icon) → set Backend URL to http://localhost:4000 and Website URL to http://localhost:8080, then Save.

Full architecture, environment variables, and API reference: see server/README.md and the root README.md in the submission.
